# R2 Phase 1.2: JSON Save Variants + Batch Category Audit

## Part A: Local Save-Json Variant Catalog

### Canonical Reference: `lib/Serialization.psm1:Save-Json`

Key features of the canonical implementation:
- `[CmdletBinding()]` with `[Parameter(Mandatory)]` attributes
- Parameters: `$InputObject`, `$Path`, `$Depth` (default 20), `$NoBom` switch
- **Path-traversal guard**: rejects paths containing `..`
- **Null/empty path guard**: throws on null/whitespace `$Path`
- Auto-creates parent directory via `New-Item`
- Uses `Set-Content -LiteralPath` (BOM) or `[System.IO.File]::WriteAllText` (NoBom)
- Depth default: 20

### Classification Key

- **Drop-in**: Same signature as canonical `Save-Json`; can be replaced with a one-line call. (None found -- all differ in at least parameter names or signature.)
- **Adaptable**: Different signature or minor behavior differences, but can be replaced by calling `Save-Json` from `Serialization.psm1` with appropriate parameter mapping. All 16 variants fall here.
- **Incompatible**: Fundamentally different semantics that prevent replacement. (None found.)

### Gap Analysis vs. Canonical

All 16 local variants share these **missing security features** compared to the canonical:

| Gap | Affected Variants | Risk |
|-----|-------------------|------|
| No path-traversal guard (`..` check) | All 16 | Medium -- allows writing outside intended directory if path is user-influenced |
| No null/empty path validation | 14 of 16 (only `05` and `06` partially guard) | Low-Medium -- could cause silent failures or writes to CWD |
| Inconsistent depth values (6-50) | All 16 | Low -- may truncate deep objects or waste cycles on shallow ones |
| Mixed encoding (BOM vs NoBom) | 10 use BOM, 6 use NoBom | Low -- inconsistent JSON files across proof outputs |
| Silent error swallowing | `01`, `06`, `09`, `16`, `17`, `19` | Medium -- write failures go unnoticed |

### Consolidation Recommendation

All 16 variants are **Adaptable** and should be replaced with calls to `lib/Serialization.psm1:Save-Json`. Migration pattern:

```powershell
# Before (local variant):
Save-Json -Obj $proof -Path $proofPath

# After (canonical):
Save-Json -InputObject $proof -Path $proofPath -Depth 20 [-NoBom]
```

Scripts currently using NoBom encoding (`04`, `05`, `20`) should pass `-NoBom`. Scripts using high depths (`11`: 50, `09`: 40, `12`: 30) should evaluate whether depth 20 (canonical default) is sufficient.
