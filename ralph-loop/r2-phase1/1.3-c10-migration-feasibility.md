# R2 Phase 1.3 -- C10 Findings Pattern Migration Feasibility

## Standard Pattern (lib/Results.psm1)

```powershell
$Findings = New-FindingsList                    # typed Generic.List[object]
Add-Finding -Code 'X' -Severity 'Y' -Message 'Z' [-Extra @{...}]
# V2 contract: -Findings @($Findings)
```

Fields: **Code**, **Severity**, **Message** (mandatory); TypeName, ProfileName, Extra (optional).

## Moderate -- Migration Details

These scripts have a findings-like concept but use different variable names or structures.

### 06 -- UpdateHealth-SSU-Proof
- **Current:** Custom `New-Finding` function returns `{Time, Area, Severity, Message}`. Uses `ArrayList` named `$findings`, `$notes`, `$actions`.
- **Migration:** Rename `Area` to `Code`. Map Severity values (Info/Warning/Error to standard). Replace `New-Finding` calls with `Add-Finding`. Replace ArrayList init with `New-FindingsList`. Remove custom `New-Finding` function.
- **Effort:** ~30 min. ~20 call sites.

### 10 -- SupportBundle-Parser
- **Current:** `$findings = @()` with string concatenation (`$findings += "message"`).
- **Migration:** Replace string array with `New-FindingsList`. Convert each string append to `Add-Finding` with appropriate Code (e.g., `SB-ZipMarker`, `SB-MissingProof`, `SB-MissingKB`) and Severity. Replace `New-Findings` helper function.
- **Effort:** ~15 min. 5 call sites.

### 20 -- MissingPatch-Notification
- **Current:** `$zeroDays` and `$missingCritical` are arrays of KB objects. No findings list.
- **Migration:** Add `New-FindingsList` init. Loop over `$zeroDays` to add High findings, `$missingCritical` to add Medium findings. KB details go in Extra.
- **Effort:** ~15 min. Simple loop additions.

### 24 -- Cert-AutoEnrollment-Health
- **Current:** Single result object with aggregated booleans. No findings list.
- **Migration:** Add `New-FindingsList` init. Generate findings for: expiring certs (one per cert, Severity by days-to-expiry), autoenrollment failure, missing operational log.
- **Effort:** ~20 min. Need to identify finding-worthy conditions in the result assembly.

### 25 -- WinGet-Config-Baseline-Runner
- **Current:** Summary object with FinalExitCode. Phase results as objects in a list.
- **Migration:** Add `New-FindingsList` init. Generate a finding per failed phase (validate/test/apply).
- **Effort:** ~15 min. Simple conditional adds.

### 29 -- Network-Config-Audit
- **Current:** `$issues` array computed from `$interfaces` (missing DNS/gateway).
- **Migration:** Add `New-FindingsList` init. Loop over `$issues` to add findings with interface details in Extra.
- **Effort:** ~15 min. Clean mapping from issue objects to findings.

## Hard -- Migration Details

These scripts use fundamentally different collection mechanisms (plain strings, multiple parallel lists) that require significant restructuring.

### 04 -- OfficeBrowser-Hardening-Proof
- **Current:** `$globalNotes` (List[string]) for informational messages. `$allItems` (List[object]) for per-item compliance results with `Compliant`, `Changed` fields.
- **Migration:** Each non-compliant item should become a finding. Notes can become Info-severity findings. Requires iterating the compliance items post-evaluation and mapping Category/Name/Compliant to Code/Severity/Message. The existing `$allItems` schema is rich (Section, Name, Value, Expected, etc.) and would need to be flattened into findings with Extra.
- **Effort:** ~45 min.

### 05 -- WUFB-Proofing
- **Current:** `$changes`, `$drifts`, `$notes` as typed List[string]. `$ops` as List[object] with `{Path, Name, Before, After, Changed, Drift}`.
- **Migration:** Each drift string needs a Code (derived from registry key name) and Severity. The `$ops` objects have better data but require mapping their fields. Would need to interleave findings generation with the existing registry-check flow.
- **Effort:** ~60 min. Many scattered Add-Result calls.

### 07 -- ScheduledTasks-Hygiene
- **Current:** `$drifts` and `$changes` as List[string].
- **Migration:** Drift strings are terse ("Critical missing: pattern"). Would need to wrap each drift addition with an Add-Finding call, assigning Codes like `TASK-CriticalMissing`, `TASK-SuspiciousArgPath`, etc.
- **Effort:** ~45 min. Many drift addition points throughout the script.

### 14 -- SecureRemoteAccessGuardrails
- **Current:** `$changes`, `$drifts`, `$notes` as plain arrays (`@()`). Drift strings like "fDenyTSConnections 1 != 0".
- **Migration:** Similar to 05. Each registry-check drift needs a Code and Severity. The helper functions (`Ensure-RdpFirewallRules`, `Ensure-RdpGroupMembership`, `Ensure-RemoteAssistance`) return mixed change/drift strings that need classification.
- **Effort:** ~60 min. Requires refactoring helper return types.

### 15 -- HardwareTPM-Audit
- **Current:** `$drifts` and `$notes` as List[string]. `$errors` as List[string].
- **Migration:** Drift strings like "TPM SpecVersion '1.2' does not satisfy MinVersion '2.0'" need Code and Severity. The proof object structure should remain but findings should be generated in parallel.
- **Effort:** ~30 min. Moderate number of drift-addition points.

### 16 -- Sysmon-Config-Updater
- **Current:** `$actions`, `$warns` as plain arrays. `$summary` as ordered hashtable.
- **Migration:** Warnings could become findings. Actions are operational (not findings). Need to identify which warnings merit findings vs. informational notes.
- **Effort:** ~30 min.

## Incompatible -- Rationale

These scripts cannot meaningfully use the findings pattern without fundamentally changing their purpose.

| # | Script | Reason |
|---|--------|--------|
| 03 | LocalAdmins-Guardrail | Outputs a single guardrail result object with drift expressed as boolean flags and member arrays. Could add findings *in addition to* existing result, but drift semantics are at the object level, not per-finding. |
| 09 | SupportBundle | Data-collection tool (creates ZIP). No audit/compliance concept. |
| 17 | Sysmon-Rule-Drift-Sensor | Statistical drift analysis with per-rule ratios/baselines. Results are quantitative, not qualitative findings. |
| 19 | Software-Audit | Inventory enumeration and compliance testing. Results are per-software items, not drift findings. |
| 21 | EmergencyKillSwitch | Operational action tool (network isolation). Tracks actions taken, not audit findings. |
| 26 | Get-WinEvent-FastTriage | Event log dump/triage tool. Outputs raw events for analysis. |
| 30 | Service-Process-Audit | Data-collection/reporting tool. Lists processes and services with resource usage. |
| 42 | Client-SecurityBaseline-Report-IntuneRef | Tabular baseline comparison report with per-field match semantics. Schema is columnar, not suitable for flat findings list. |

## Recommended Migration Order

Priority: Easy wins first (Moderate), then Hard. Incompatible scripts are excluded.

### Phase 0 -- Easy (1 script, ~2 min)

1. **33 -- AdvancedAuditPolicy-Audit** (change `New-Object System.Collections.ArrayList` to `New-FindingsList`, 1-line fix)

### Phase A -- Moderate (quick wins, 6 scripts)

1. **10 -- SupportBundle-Parser** (5 call sites, string-to-finding, ~15 min)
2. **20 -- MissingPatch-Notification** (loop over KB arrays, ~15 min)
3. **29 -- Network-Config-Audit** (loop over issue interfaces, ~15 min)
4. **25 -- WinGet-Config-Baseline-Runner** (per-phase findings, ~15 min)
5. **24 -- Cert-AutoEnrollment-Health** (condition-based findings, ~20 min)
6. **06 -- UpdateHealth-SSU-Proof** (rename Area->Code, remap Severity, ~30 min)

### Phase B -- Hard (requires more refactoring, 6 scripts)

1. **15 -- HardwareTPM-Audit** (string drifts to findings, ~30 min)
2. **16 -- Sysmon-Config-Updater** (warnings to findings, ~30 min)
3. **07 -- ScheduledTasks-Hygiene** (string drifts to findings, ~45 min)
4. **04 -- OfficeBrowser-Hardening-Proof** (compliance items to findings, ~45 min)
5. **14 -- SecureRemoteAccessGuardrails** (helper refactor needed, ~60 min)
6. **05 -- WUFB-Proofing** (scattered Add-Result calls, ~60 min)

### Not recommended for migration

Scripts 03, 09, 17, 19, 21, 26, 30, 42 -- fundamentally different purpose or data model.
