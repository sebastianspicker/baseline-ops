## Intentionally Deferred

| Finding | Reason |
|---------|--------|
| M1 (Write-ConsoleSummary) | 21 scripts have script-specific `Write-ConsoleSummary` with completely different signatures and logic. These are not true duplicates; they share a name but serve different purposes per script. Requires a design-level refactor to create a pluggable summary system. |
| M8 (Get-StatusColor) | 4 scripts have domain-specific color logic incompatible with the generic lib version. Local versions handle status values that the lib does not map. |
| L5 (hardcoded C:\install\mdm\ps1) | This is the standard deployment path for the project, used as parameter defaults across 5 files + help text. Changing to an env var would require all deployed endpoints to set the variable, introducing deployment risk. The values are already overridable via parameters. |
| L13 (CmdletBinding - bulk) | ~160 script-local functions across 30+ scripts lack `[CmdletBinding()]`. Adding it to all is a massive change with potential for parameter binding behavior changes (as demonstrated by the Has-Property issue). Fixed for 00-Copy-Local.ps1 as a representative sample. Remaining functions should be addressed incrementally per-script. |
| I1 (ForegroundColor vs Style) | 201 uses of `-ForegroundColor` across 26 scripts. This is a style preference, not a bug. The alias works correctly via `Resolve-UiColor`. Addressed the most problematic cases (DarkCyan, DarkYellow, DarkGray) that either used invalid colors or bypassed semantic tokens. |
| I2 (SB_ prefix in 09-SupportBundle) | 30 functions use non-standard `SB_*` naming. This script predates the lib consolidation and has its own parallel utility layer. Renaming would be a major refactor with high breakage risk. |
| I6 (00-Run-Batch no Bootstrap) | Architectural decision -- this script constructs a temp profile and delegates to 00-Run-Profile.ps1, which does load Bootstrap. |
| C10 (Findings pattern, remaining 20 scripts) | These use drift/notes/string-based patterns incompatible with New-FindingsList/Add-Finding. Conversion requires business logic changes per Phase 2.3 analysis. |
